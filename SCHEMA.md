# Схема данных и миграции

Бэкенда нет: единственная копия данных пользователя лежит в `localStorage` его браузера.
Значит, любое изменение структуры данных — это изменение чужой базы, которую нельзя
пересоздать. Отсюда правила ниже.

## Где что лежит

| Ключ | Что | Можно ли менять |
| --- | --- | --- |
| `drss-portfolio:v1` | рабочие данные | **имя ключа не менять никогда** — другой ключ равен потере данных у всех |
| `drss-portfolio:backup` | копия данных, снятая автоматически перед первой миграцией | служебный, приложение только пишет |

Версия схемы хранится **внутри данных**, в поле `version`, и объявлена в `src/storage.js`
как `export const VERSION`. Суффикс `v1` в имени ключа — историческое название, к версии
схемы отношения не имеет и остаётся неизменным.

## Текущая версия: 1

```
{
  version: 1,
  employees: [{
    id, name, position, managerId, format, officeDays, rate, status,
    startDate, skills, note
  }],
  projects: [{
    id, name, code, type, customer, managerId, status, startDate, endDate,
    basis, budget, plannedFte, note,
    assignments: [{ employeeId, percent }]
  }]
}
```

Допустимые значения справочников — в `src/model.js` (`POSITIONS`, `FORMATS`, `RATES`,
`EMPLOYEE_STATUSES`, `PROJECT_STATUSES`, `PROJECT_TYPES`).

## Как менять схему

1. **Поднять `VERSION`** в `src/storage.js` на единицу.
2. **Добавить миграцию** в объект `MIGRATIONS` там же. Ключ — версия, *из* которой
   переводим; функция возвращает данные с новым `version`:

   ```js
   const MIGRATIONS = {
     1: (d) => ({
       ...d,
       version: 2,
       projects: d.projects.map((p) => ({ ...p, priority: '' })),
     }),
   };
   ```

   Миграции применяются по цепочке `1 → 2 → 3`, поэтому пропускать промежуточные номера
   нельзя: копия годовой давности должна пройти через все шаги.
3. **Добавить поле в `normalize()`** с безопасным значением по умолчанию — это последний
   рубеж для данных, пришедших из чужого файла.
4. **Дописать строку в таблицу истории** выше.
5. **Проверить на старой копии**: `npm run dev`, кнопка «Загрузить из файла», взять JSON,
   скачанный до изменения. Импорт старых копий ломать нельзя.
6. `npm run build` — сборка должна проходить.

## Что миграция делать не должна

- Удалять данные пользователя. Ненужное поле лучше перестать показывать, чем стирать.
- Падать на неполных данных: в старых копиях поле может отсутствовать или быть `null`.
- Молча терять записи. Если запись невозможно перевести — оставьте её как есть,
  `normalize()` подставит значения по умолчанию.

## Что происходит при загрузке

`loadData()` читает ключ → если `version` меньше текущей, кладёт исходную строку в
`drss-portfolio:backup` → `normalize()` проверяет структуру → `migrate()` прогоняет цепочку
миграций → поля приводятся к текущему виду. Любая ошибка чтения возвращает `null`,
и приложение стартует с начальными данными вместо белого экрана.

Данные новее приложения (например, пользователь открыл старую вкладку) не затираются:
`migrate()` бросает ошибку с понятным текстом, импорт отклоняется.
